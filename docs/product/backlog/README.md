# PEEL Backlog - Post-MVP Features

This directory contains feature planning for post-MVP development. These epics are not required for the 0.1 MVP release
but are valuable enhancements for future versions.

## Backlog Epic Status

### High Priority

**EPIC-08: Compiled Programs**

- **Status**: Planned
- **Priority**: Medium-High
- **Complexity**: Low-Medium
- **Risk**: Low
- **Goal**: Parse once, evaluate many times with different inputs
- **Value**: Performance optimization (50-90% improvement) + cleaner API
- **Use Cases**: Template expressions, rule engines, validation, batch processing

**Dependencies**: MVP Complete (Epic 1-6)

**Quick Win**: High value, relatively low complexity. Good early post-MVP feature.

---

**EPIC-07: External Objects**

- **Status**: Planned
- **Priority**: Medium-High
- **Complexity**: High
- **Risk**: High (Security-critical)
- **Goal**: Allow host applications to register Java objects with whitelist-based access
- **Value**: Enables PEEL as embedded expression language
- **Security**: Requires security review before implementation

**Dependencies**: MVP Complete (Epic 1-6), Security expertise available

## Prioritization Criteria

When deciding what to implement next:

1. **Security**: Security-critical features (like Epic 7) need security expertise
2. **Value vs Complexity**: High value, low complexity = quick wins
3. **User Demand**: What do actual users request?
4. **Dependencies**: What unlocks other features?
5. **Learning**: What teaches valuable skills?
6. **Fun**: It's a hobby project - what's interesting?

## Rationale

**Why Epic 8 first?**

- Unlocks REST API, REPL, and validation use cases
- Performance critical for production use
- Low risk, high value
- Foundation for everything else

**Why Standard Library early?**

- User rated 5/5 ("Yeah we need that")
- Can grow incrementally
- Makes PEEL actually useful
- Low risk to add functions

**Why REPL before REST API?**

- Both rated 5/5, both depend on compiled programs
- REPL is simpler and aids development
- REST API benefits from REPL for testing

**Why External Objects later?**

- Security-critical - needs careful implementation
- High complexity
- Not needed until embedded use case proven
- Do the easy wins first

**Why Partial Evaluation high priority?**

- User insight: "Debugger is basically built in"
- High value for debugging
- Medium complexity
- Better than full debugger (Rating: 1/5)
